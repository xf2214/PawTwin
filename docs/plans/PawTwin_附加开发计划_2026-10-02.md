## 2. 产品定位与冲奖路径

定位：**有个体上下文、能协调家庭照护的宠物 AI 分身**。
每只宠物有持续更新的档案、成长事实、确认偏好和近期观察。App 风格网页与 Alexa 体验共用分身；像素小屋呈现有依据的状态和任务结果。
主场景：家人查清谁已做过什么，结合宠物偏好安排照护，确认后执行或记录，下一会话接着使用这些信息。

候选赛事按 2026 Build, Ship, Shape 的 Alexa+ 与 AWS Builder 规划；用户明确“Alexa AWS”，但未提供正式活动链接/报名记录。最终活动、资格与赛道提交前确认。

技术、设计、用户价值、创意同等权重；跨会话上下文和跨服务任务执行是主办方强调的方向。[主办方说明](https://amazonappdev2026.devpost.com/updates/46456-got-an-idea)

先做家庭共享和准确记录，再做统计/记忆/受控行动，随后真实云验证、用户试用和演示。自动照片识别、额外动画、真实硬件与原生客户端后置；不承诺获奖概率。

1. 建档与形象：手动建档可用；上传/拍照识别只给候选，主人确认后保存；模板形象可编辑，不从照片认定年龄、健康或喜好。
2. 小屋交互：保持 2D 俯视房间，宠物正常正面/侧面造型；物品对应资料、照护入口和有来源的状态。
3. 计划：人工喂食、换水、陪玩、梳毛、洗澡、剪指甲、清洁、散步；周期由主人设置，补齐领取、转交、编辑、取消。

5. 家庭交接：独立成员账号共享资料，实际操作人由登录身份确定。
6. 成长照片：照片/文字时间线关联称重与照护事件，日/周回顾只使用有效记录。

## 5. 独立账号、身份与家庭共享

### 5.1 使用流程与角色

用户独立登录后创建家庭或接受邀请；设置头像、昵称和家庭称呼。称呼可选爸爸、妈妈、姐姐、哥哥、室友、照护人、自定义。
称呼由本人选择，权限由管理员授权；选择“爸爸”不会获得管理权，成员不能自行升级权限。

| 权限类型 | 默认能力 |
|---|---|
| 管理员 | 家庭设置、邀请/移除、成员权限、宠物资料管理 |
| 照护成员 | 查看共享内容、记录观察/照片、领取和完成允许的任务 |
| 访客 | 查看指定内容，临时照护按额外授权开放 |

喂食审批单独绑定宠物与获授权成员；任何角色都不能绕过份量/间隔限制。
邀请有有效期、撤销和使用限制，重复接受不产生重复关系；保存邀请令牌摘要，不记录明文到日志。
退出/移除后新的 API、图片和 Agent 工具请求立即拒绝，不能仅隐藏按钮或等待令牌自然过期。
最后一名管理员退出前移交管理权；历史记录保留稳定作者 ID 与当时展示名。

### 5.2 共享与数据归属

家庭共享档案、确认偏好、成长照片、照护计划、完成记录和设备回执；个人账号资料及私密对话不默认共享。
进入宠物公共记忆的内容明确标识并按需要确认。操作作者由后端取登录身份，不能提交其他 actor_id 冒充家人。
资料以 `household_id` 归属、`pet_id` 隔离、`user_id` 追溯；每次请求检查当前成员关系和动作权限，不能仅信任前端传来的家庭 ID。
照片、报告、记忆、AI 工具、审批和设备额度执行相同范围校验。首版可聚焦一个当前家庭，结构保留多家庭扩展能力。

AWS 独立登录优先评估 Cognito；家庭关系由业务后台维护，不能用全局登录组替代家庭权限。[Cognito 文档](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools.html)
本地多身份测试与真实云登录分列，不用显示名或测试令牌冒充云认证完成。

### 5.3 迁移与协作可靠性

迁移覆盖旧 Home 文档、照片、任务以及喂食仓储，不能只将 owner 字段改名。
旧 Mochi/配额明确映射到家庭和宠物；不同账号不能各复制一份额度控制同一设备。
先备份并在库副本上做幂等迁移、计数/关联核对和失败恢复，未经验证不破坏正在使用的 `data/pet-home.db`。
任务按周期实例处理，领取/完成/审批通过条件更新或版本冲突控制；两个成员同时提交只产生一个有效结果。
先完成前台可靠同步，后续再选实时推送；任务提醒、报告生成与通知送达分别记录，不假报成功。

## 6. 成长数据与自动日/周统计

### 6.1 原始事实

称重包含记录 ID、家庭/宠物、重量/单位、测量时间、录入时间、作者、来源、备注、版本及纠错/删除状态。
来源区分主人实测、兽医资料、已验证设备和演示样本；照片不生成猜测体重。生日估计要标记，幼龄展示周/月。
饮食区分出粮、提供食物、主人记录实际摄入及剩余；热量有标签/资料来源，不从克数编造。
换水次数不等于饮水量，陪玩完成不等于传感器测得活动量。

### 6.2 统计口径

存储 UTC/明确时区，默认家庭时区 Asia/Shanghai，可配置。日报按家庭本地日，周报按周一 00:00 至下一周一 00:00。
报告带统计窗口、截止时间、覆盖情况、源记录 ID、版本与生成状态。

| 指标 | 规则 |
|---|---|
| 照护 | 有效完成/待办/逾期/负责人；人工完成与设备成功分列 |
| 体重变化 | 至少两次有效测量，单位统一；差值与差值/比较值；比较值大于零 |
| 周趋势 | 显示实际测量跨度，周期内数据不足则说明，不把月跨度说成本周变化 |
| 饮食 | 实际摄入、出粮分列；未记录表示缺失，不填零 |
| 协作 | 成员任务与交接记录，不按数量推断照护质量 |
| 成长 | 有效照片/日记与相关事件，修订删除后重算 |

算术演示：9 月 25 日 1.20 kg、10 月 2 日 1.35 kg，相隔 7 天，增加 150 g、12.5%；不据此认定健康。
日报不要求每天称重；只有一次称重时不能计算增重，没有称重的日期不编造每日体重。
程序算数值，AI 解释已有事实与统计，不能替换结果或填补缺失数据。

### 6.3 自动报告与修订

记录变更刷新统计；持久化调度每日/每周生成，可重试、服务重启补跑，不只依赖用户打开网页。
同家庭/宠物/周期只保留一个当前有效版本；迟到、修订、删除使旧报告失效并重建。
记录生成时间、统计版本和失败状态；生成不等于发送，发送不等于已送达。

## 7. 个体分身与统一上下文

| 层 | 信息 | 可信边界 |
|---|---|---|
| 基础档案 | 品种确认状态、生日、性别、绝育、家庭 | 缺失不猜测 |
| 成长事实 | 称重、饮食、照片、照护、兽医资料 | 保留测量时间和来源 |
| 个体记忆 | 确认过的偏好、习惯与反馈 | 提取候选须确认，不直接当事实 |
| 近期状态 | 今日观察、任务、报告 | 有时效，过期不永久引用 |
| 参考知识 | 品种、生长、照护资料 | 有来源/版本/适用范围，和个体事实区分 |

建档自动产生初始上下文，新记录更新摘要，日/周报告补充成长变化；每次问答仍取最新原始事实和相关记忆。
上下文是结构化可追溯快照，不是无限堆叠提示词。包含 `context_version`、`as_of`、源版本、有效期与未解决冲突。
用户能查看分身记忆并确认、纠正、删除；修订后旧摘要和后续检索停止使用失效内容。家庭成员的矛盾观察明确标记，不静默合成确定结论。
家庭公共记忆与个人私密内容分开；家庭/宠物范围和成员权限对检索同样生效。
AgentCore 提炼/检索须有真实 record ID 和证据；普通数据库保存/查询不冒充 AgentCore。

App 点宠物、助手和 Alexa 模拟入口调用同一上下文与工具服务，不维护两套分身。
每轮确认当前家庭/宠物；代词不清时询问，不能把其他宠物资料默认当 Mochi。
分身可用统一头像/昵称/亲切口吻，第一人称有主人记录依据，不宣称真实动物语言翻译。
模型、记忆和报告不能赋予权限；写入是待确认方案或获授权记录，设备执行仍经规则、审批和回执。
真实 Alexa 平台接入仅在实测后升级标签；MCP 可后置，不用空接口包装代替闭环。

## 8. 品种知识、成长参考和健康问题

“它喜欢什么”优先个体记录；“该品种通常有什么习性”提供有来源概括，不认定个体必然如此。
“三个月通常多重”直接读取已建档信息，核对周龄、性别、体型/预期成年体重，只追问缺项。
参考资料保留 URL、获取日期/版本、物种/年龄/体型范围与审核状态。无适用参考就说明缺少依据，不生成标准体重。
WALTHAM 幼犬曲线从 12 周龄验证，按体型/性别选择；幼猫曲线从 8 周龄验证，有成年体重范围限制。群体参考不能直接成为个体诊断。[幼犬资料](https://www.waltham.com/resources/puppy-growth-charts)、[幼猫资料](https://www.waltham.com/resources/kitten-growth-charts)

“是否营养不良”回答包含已有趋势、缺失饮食/食欲等信息、可靠知识解释和需要兽医评估的提示，不因低于均值就确诊或自动加粮。
体重应结合体况和肌肉状况等评估；可生成真实记录的就诊摘要，照片与模型不替代检查。[营养评估资料](https://www.merckvetmanual.com/management-and-nutrition/nutrition-small-animals/overview-of-nutrition-small-animals)
健康问答保持准确表达，不用分身语气编造“我确定生病了”。具体风险提醒/升级规则在 EXT-09 按可靠资料审核，不在这里虚构诊断阈值。
