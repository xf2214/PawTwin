# PawTwin 五个工作日开发总方案

本方案将 PawTwin 收敛为一个可运行、可测试的宠物照护 Agent。比赛原型真实实现 AWS 推理、历史查询、个体记忆、主人审批和任务记录；PawLink 佩戴设备作为概念展示，传感器输入和设备动作使用明确标注的模拟器。

用户已确认：开发周期为五个工作日；目前没有 AWS 账号；编码、测试、审查、部署准备和材料整理全程由 Agent 承担。本次交付为开发计划，尚未开始实现、创建云资源或产生 AWS 费用。

## 1 产品目标与范围

一句话定位：PawTwin 结合一只宠物的历史与主人观察，帮助家庭理解照护请求、确认行动并记录结果。

首个目标场景是家庭成员之间信息不同步造成的重复喂食与照护遗漏。本次只支持一只虚构宠物 Mochi、一个家庭、一个演示操作者，不建设多家庭账户体系。

| 本次真实实现 | 本次模拟 | 仅概念与路线图 |
|---|---|---|
| AWS 模型推理与工具调用 | 位置、声音、活动等事件输入 | PawLink 项圈外观、佩戴形态 |
| 历史查询与主人反馈保存 | 喂食器命令与成功/失败回执 | 真实传感器、续航、防水、蜂窝通信 |
| AgentCore 长期记忆检索 | 演示历史样本，明确标注来源 | 叫声意图模型训练、GPS 防丢 |
| 审批、拒绝、配额检查、执行记录 | 宠物表达为有依据的推测文案 | 六维画像、饥饿预测、医疗判断 |
| 真实网页、持久化、运行日志 | 执行器可人为注入失败 | Alexa+，除非核心完成后已有可用权限 |

范围上限：一个网页、一个产品 Agent、一个模拟执行器、三种核心场景。开发过程可以使用多个 Agent，产品不使用多 Agent 编排。

不要求用户写代码、安装硬件或标注训练数据。也不承诺已经识别宠物真实心理状态。

## 2 三种核心场景

### 场景 A 正常照护

模拟器发送请求事件；Agent 实际查询当前记录与相关记忆；程序检查允许的动作；页面展示具体动作及理由；主人批准；模拟执行器产生回执；收到成功回执后才更新任务与喂食记录。

### 场景 B 已经喂过

在演示输入区新增一条近期喂食记录，再发送相同类型的新事件。系统读取新事实并停止额外喂食。重复上传同一事件 ID 不得创建第二个任务。是否可以执行由程序策略决定，不能被模型措辞或记忆覆盖。

### 场景 C 个体记忆影响建议

主人记录“我观察它饭后这样做，有时是在找人陪玩”。反馈先保存到业务记录，长期记忆显示处理中；待 AgentCore 确认可检索后，开启新会话，再发送相关事件。Agent 引用这条主人观察提出陪玩建议，并保留不确定性。

演示不要求现场几秒内完成长期提炼。预先准备一条已提炼的演示记忆用于主视频；现场新反馈则真实显示处理状态。不能用本地反馈查询冒充 AgentCore 检索成功。

## 3 最小界面

只做一个网页，包含三个主要区域及一个折叠的演示控制区。

| 区域 | 显示与操作 |
|---|---|
| 宠物与请求 | Mochi 形象、最新请求、来源标签；“推测表达”标识 |
| 建议与确认 | 当前建议、真实依据、策略结论、具体动作参数、批准/拒绝 |
| 任务与记忆 | 任务状态、模拟回执、历史事件、主人反馈、记忆处理状态 |
| 演示控制区 | 修改最近喂食时间、注入事件、选择模拟器成功/失败、新会话 |

固定展示三条边界：传感器事件为模拟；设备执行为模拟；项圈为概念设计。开发模式的“本地替身”与正式演示的“AWS 已连接”也必须有不同标识。

不展示模型隐藏推理过程。证据面板只呈现实际查询记录、工具名称、简短决策解释和执行结果。

## 4 默认实现方式

采用 React + TypeScript 页面，Python FastAPI 同时提供接口与构建后的静态页面。Strands 在同一应用内组织一个 Agent，调用 Bedrock。一个容器部署到 ECS Express Mode，避免拆分多个服务。

| 组件 | 职责 |
|---|---|
| Bedrock | 结合真实查询结果生成结构化建议 |
| Strands | 调用有限的查询工具，不持有绕过审批的执行工具 |
| DynamoDB | 当前事实、任务状态、审批、反馈原文、模拟回执和去重记录 |
| AgentCore Memory | 主人观察和偏好的长期提取、跨会话检索 |
| ECS Express Mode | 部署单容器网页/API/轻量后台任务 |
| ECR 与 CloudWatch | 镜像与精简日志 |

本地无账号时使用 SQLite 和明确标记的模型/记忆替身完成联调；正式云端模式禁用悄悄回退到替身。云服务失败必须显示失败或降级，不能返回预制成功答案。

默认一个应用副本；滚动更新仍可能短暂出现两个进程，任务领取、批准和执行都要有数据库条件更新与幂等约束。任务先入库，再由应用内轻量 worker 处理，不能只放在进程内存中。

暂不引入 IoT Core、SageMaker 训练、AgentCore Runtime/Gateway、Step Functions、独立消息队列、自定义域名或复杂账户系统。

ECS Express Mode 是拟定默认，不是最低费用承诺。账号就绪后先核实区域、资源支持、权限和费用；如超出用户预算，先调整部署设计再创建资源。AWS 当前已说明 App Runner 对新客户关闭，故不作为新账号默认选项。[1][2]

## 5 Agent 分工与协作规则

同时最多四个活动 Agent，包括总负责人。角色按阶段复用，不同时启动所有角色。

| 角色 | 负责范围 | 不能自行决定的事项 |
|---|---|---|
| 总负责人 Agent | 接口、范围、任务派发、集成、验收、变更记录 | 不跳过云端验证宣称完成 |
| 后端 Agent | 数据、策略、状态机、审批、模拟器、恢复 | 不改前端接口约定、不绕过配额 |
| AI Agent | Bedrock/Strands、证据归因、AgentCore Memory | 不新增执行权限、不把推断当事实 |
| 前端 Agent | 单页界面、状态、输入模拟、可见边界 | 不伪造接口成功、不内置云端答案 |
| 云部署 Agent | IAM、镜像、部署、预算与删除清单 | 不擅自开高规格资源或放宽为管理员权限 |
| 独立审查 Agent | 审批绕过、并发、记忆、部署验收与材料一致性 | 不以实现者自评代替测试 |

第一步冻结接口，再并行实现。每个任务限定可写文件范围；共享契约仅由总负责人修改。可用 Git 时在实施开始创建仓库和任务分支，独立写代码使用隔离工作树；不能建立隔离时采用不重叠文件所有权并顺序集成。

每次交接必须包含：改动文件、完成项、实际运行的检查、失败项、云端/替身状态、下一步依赖。独立审查先核对范围，再审查实现。总负责人修复问题后重新执行相关检查，不能仅合并代码即交付。

## 6 五日安排

这里的“日”是工作包顺序，不是无条件的完成承诺。估计依据是范围冻结、已有开发工具可用、AWS 账号与权限及时准备；实际耗时以首次运行结果调整。不会创建后台定时任务，后续开发在本任务内按阶段推进。

| 工作日 | Agent 主线 | 用户参与 | 当日验收与产物 |
|---|---|---|---|
| 第 1 日 | 冻结接口；建立本地项目；完成输入、任务持久化、策略测试；前端接真实本地 API；并行准备云接入清单 | 注册 AWS、完成账户与付款验证、启用 MFA、提供目标预算和比赛官方链接 | 本地正常/拒绝闭环可运行；已保存接口约定；若账号就绪则完成一次真实模型工具调用 |
| 第 2 日 | 前端/AI/后端并行：接 Bedrock、完善审批执行、建立真实查询证据 | 完成必要的模型使用条款或登录 | 云模型参与正常与重复喂食场景；未批准零执行；模型与工具调用记录可核查 |
| 第 3 日 | 接 AgentCore；反馈与跨会话检索；持久化领取、并发和重启恢复 | 试用并指出不清楚的文案 | 三场景打通；记忆来源与处理状态清楚；并发批准和重复事件不产生重复逻辑动作 |
| 第 4 日 | 云部署；独立审查；浏览器验收；针对失败修复 | 对具体资源、预计费用及运行期限作一次确认 | HTTPS 演示可访问；访问控制、刷新、重启和失败回执通过；可部署可删除 |
| 第 5 日 | 冻结功能；测试与评委自由输入；生成佩戴概念素材、演示脚本、英文提交材料和演示录屏 | 核对署名、事实与对外发布内容 | 发布候选版本、验证报告、三分钟演示、源码与部署说明、已实现/模拟/路线图清单 |

账号准备不能拖到最后一天。第 2 日开始仍无真实 AWS 调用时，继续本地工作，但云端里程碑按实际阻塞顺延，保留第 4、5 日对应的验证和材料工作量，不能把本地替身标记为参赛完成。

发布代码仓库、提交比赛和正式对外材料发送由用户明确授权后执行。本计划不自动提交比赛。

## 7 用户只需承担的节点

1. AWS 注册、身份/付款验证、MFA 和服务条款。Agent 可以指导，但不代替你提供身份或支付信息。
2. 通过本机登录或临时角色授权开发，不将长期密钥粘贴到聊天或提交到仓库。
3. 云资源创建前确认一份具体的预算估算、运行期限和删除清单；Agent 先完成所有可本地完成的准备。
4. 第一次可用演示的产品反馈，以及最终参赛署名、发布与提交确认。

还需要取得本次比赛的官方链接、截止时间和规则文本。已有上下文仅给出“AWS 黑客松”，此前引用的 2025 赛事已经结束，不能当作本次规则已核实。该核查由 Agent 在拿到链接后完成，当前规划不因此中断。

## 8 必须通过的验收

| 编号 | 场景 | 判据 |
|---|---|---|
| A01 | 正常请求 | 查询记录可追溯；批准后才执行；成功回执后才显示完成 |
| A02 | 未批准与拒绝 | 零执行；刷新与重试不改变拒绝结果 |
| A03 | 审批后参数或事实变化 | 旧批准不能用于新动作；执行前重查策略；失效时不执行 |
| A04 | 两个页面同时批准 | 同一任务最多一次逻辑执行和一次记账 |
| A05 | 同一事件重传 | 返回已有任务；新 ID 的独立事件正常处理 |
| A06 | 主人反馈与新会话 | 真实检索 AgentCore 记忆；显示来源；不能硬编码新答案 |
| A07 | 主人观察与模型推断 | 不把模型推断写成主人确认的长期偏好；“仅今天”不变成永久规律 |
| A08 | 当前事实与旧记忆冲突 | 当前事实与硬性策略优先；不能由记忆直接批准 |
| A09 | 信息不足 | 显示缺少的信息或建议观察；不虚构证据或执行 |
| A10 | 失败、超时、迟到回执 | 不显示虚假成功；未知状态不盲目再次执行；重复回执不重复记账 |
| A11 | 输入中的恶意指令 | 不能越过审批、身份、配额与工具范围 |
| A12 | 未授权访问 | 不能读取历史/批准任务/触发模型；浏览器无 AWS 凭据 |
| A13 | 等待审批或处理中重启 | 状态可恢复；终态不重新执行；处理锁有期限 |
| A14 | 随机改演示事实 | Agent 依据变化；不按场景名称返回预制答案 |

20–30 条固定案例仅验证工作流与建议的一致性，不作为真实宠物意图准确率。报告实际结果，禁止提前填入准确率或成功率。

## 9 费用、演示数据与退出方式

正式演示只用虚构宠物和可公开的人工样本。单操作者访问采用服务端校验的演示登录、短期会话和权限检查；不开发用户注册平台。评委使用单独配置的演示口令，口令通过私有测试说明交付，不写入公开源码。

默认限制每个登录会话同时一个分析任务、全站同时两个分析任务、每个任务最多四次模型调用、单次输出最多 800 tokens；这些是应用初始上限，配置可调，真实运行后记录是否足够。日志保留七天，不写凭据或完整会话口令。

部署前列出 Fargate、负载均衡、公网 IP、日志、镜像、数据库、模型和记忆成本。预算提醒不是自动停费；应用限额也不能停止底层容器与负载均衡计费。

清理脚本必须先列出本项目拥有的资源，确认后按依赖删除，验证负载均衡、服务、镜像、日志及记忆资源是否残留。不要在正式评审要求的可访问期间自动关闭服务。

## 10 最终交付

- 可运行源码与锁定依赖，含本地启动、云端部署与清理说明。
- AWS 演示网址及测试访问方式；未完成 AWS 验证时不交付为正式参赛版。
- 自动化测试结果、实际延迟与失败案例、运行证据。
- 三分钟演示视频或在录制条件受限时明确说明限制并提供已录制片段与完整脚本。
- PawLink 佩戴概念图，醒目标明硬件未实现；图像生成需用可用图像工具，且服从赛事素材要求。
- 英文项目说明、架构说明、已实现/模拟/未来计划表；中文说明供用户审阅。
- 费用与资源清理清单、已知问题和下一步路线图。

总体执行顺序：先验证完整流程，再证明记忆价值，再部署验收，最后制作概念素材与参赛包装。若时间不足，优先移除装饰动画、额外素材和 Alexa 集成，保留真实 AWS、审批、记忆证据及验收。
