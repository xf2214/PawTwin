# PawTwin：照护交接、宠物分身与就诊信息卡

## 产品目标与本轮裁定

用户希望 PawTwin 逐步成为连接宠物主人、家人、外部照护者和就诊资料的平台。一份持续更新、有来源的宠物档案，帮助接手的人了解品种、偏好和真实日常，也让主人知道照护做了什么。

用户先选择“完善方案与产品展示”，随后明确授权本轮增加两个实际功能：导出就诊信息卡，以及由主人授权指定宠物、有效期、可撤销的宠物分身只读访问。日常上门代喂、换水、清洁、陪玩和遛狗是首批未来服务；公开市场、下单接单、支付和服务者入驻尚不开发。

本轮沿用现有 React/TypeScript 和 FastAPI/SQLite，不引入依赖、云资源或额外模型调用。保留既有家庭、数据库和像素小屋；真实能力与官网概念预览分别标注。

## 外部照护的完整构想

未来服务流程为：主人选择宠物、服务项目与时间，核对照护要求和分享资料；指定照护者接单，先通过宠物分身了解资料，再逐项记录实际服务时间、备注、照片和未完成事项；主人查看进度并核对结果。服务者提交后为待验收，不能靠超时自动变成已完成。

宠物交接资料包含基本档案、主人已确认的喜好与注意事项、近期照护与观察、待办和记录来源。外部照护者是一次服务的获授权访问者，不成为客户的永久家庭成员，也不获得修改档案、创建或确认任务、审批喂食、执行设备的权限。之后的订单系统需要独立的订单授权与审计，不能复用家庭 carer 角色直接开放全家资料。

本轮先落地资料交接：管理员选择当前宠物，设置 1/4/24/72 小时访问期限（默认 24 小时），确认共享内容后创建只读链接。链接只返回一次临时密钥，数据库保存密钥哈希；管理员可撤销，过期、宠物归档或授权管理员失去权限后访问失效。护工使用独立页面获取当前宠物上下文、提问分身，不需要加入家庭。对话明确标注本地规则，仅回顾已记录事实，不提出可执行方案或改写记录。

当前入口运行在本机本地服务；跨设备访问与真实服务运营仍需要单独部署和验证。持有链接者可在有效期内读取获授权资料，主人应自行选择接收者，项目不会替主人发送链接。

## 就诊信息卡

用户口述的“诊断卡”以“就诊信息卡（诊断资料）”呈现。它是主人记录的整理，供就诊交接参考，不生成诊断、健康评分或用药建议。

| 区域 | 内容与表达 |
|---|---|
| 基本档案 | 宠物名字、物种、品种、生日/年龄、性别、绝育情况；估计生日注明估计，手填年龄保留其原始性质 |
| 测量与饮食 | 原数值、单位、时间、来源和原备注；体重、实际摄入、提供食物、出粮、剩余分别标注 |
| 完成照护 | 所选窗口内持久化的人工完成事实、历史任务名称、完成时间与记录来源；待办不当作已完成 |
| 近期观察 | 主人陈述原文、录入时间与原作用范围；过去“仅今天”观察在历史窗口内仍可回看，不等同持续症状 |
| 偏好与日记 | 已确认偏好和窗口内的文字日记，保留来源；不包含其他宠物、账号、口令或照片资源 |
| 覆盖与缺项 | 家庭时区、近 7/30/90 天窗口、截至时间、缺失资料和来源版本；默认排除演示测量 |

流程为：选择宠物与窗口 → 生成预览 → 核对已有资料和缺项 → 打印/另存 PDF，或下载自包含 HTML 信息卡。导出使用同一份生成时刻快照；打印和下载前重新检查访问与来源是否仍有效。切宠、退出、撤权和失效请求不能导出旧宠物或其他家庭资料。

本轮不扩展饮食和观察的录入模型：食物说明暂沿用原备注，无法从备注确认食物名称时明确未记录；观察实际发生时间未录入时只展示录入时间。未知食量不能填零，记录出粮不能改写为实际摄入。过敏、用药、疫苗和就诊原因等结构化资料、可撤销的医院分享链接是后续需求，不宣称当前已有。

## 官网功能与案例演示

现有家庭应用与四项体验保留。官网新增 `#vision`，将“从了解宠物到照护交接，再到就诊准备”放进两个静态交互情景：

1. 上门照护：查看主人需求、通过授权分身了解宠物、查看服务反馈示意、主人核对。资料授权和分身访问链接到当前家庭/助手入口；预约接单与服务反馈明确为未来订单流程。
2. 就诊准备：查看资料范围、核对来源与缺项、预览信息卡结构，链接实际成长页导出入口。

示例不读取私人家庭数据、不创建任务或订单、不发业务请求。年龄、体重、摄入量和症状不编造数值；来源和空白是可视化的一部分。情景切换回第一步；键盘可操作，稳定提示区、减少动画和全局暂停继续有效。320/390/1440 屏幕适配。

## 发展路线与 Alexa+ 叙事

第一阶段是当前家庭记录、人工照护闭环、临时只读交接和就诊卡。第二阶段做指定照护者预约、订单限定资料与待验收反馈。第三阶段再评估服务者入驻、公开服务市场、通知、支付与售后。

参赛主线仍是共享宠物上下文 → Alexa 网页模拟引用记录 → 主人明确确认人工照护 → 家人完成 → 报告回看；临时交接和就诊卡补充实用场景。订单平台的概念预览作为后续发展，不替代实际演示证据。实际回答默认本地规则，Alexa 为网页模拟，硬件为模拟。

## 验收

有来源的资料范围、过期观察历史、历史照护标题、缺项/演示隔离；宠物与家庭隔离；创建/撤销管理员权限、期限/归档/成员撤权、密钥哈希与只读无副作用；下载内容安全转义、权限再校验、打印一致性；访客页面错误和撤销处理；官网无业务请求、全部情景步骤、键盘/动画/响应式；相关全量回归与独立复核。最终执行结果另见验收文档，不在计划中预写通过。
