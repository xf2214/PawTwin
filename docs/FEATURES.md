# PawTwin 功能与使用指南

PawTwin 把宠物档案、家庭照护、实测成长和有来源的个体记录放在同一个家庭应用中。日常使用围绕四件事：看看今天需要照顾什么、记录真实变化、把任务交给家人、回看完成结果。

## 功能入口

| 入口 | 用途 | 当前能力 |
|---|---|---|
| 产品官网 `/` | 了解产品、查看日常情景、进入应用 | 独立宣传页；预览与案例明确标注为示意 |
| 家庭应用 `/#app` | 日常养宠与家庭协作 | 本地账号、独立家庭、多宠物、任务与记录 |
| Alexa 网页模拟 `/#alexa` | 文字模拟口述、查看依据、确认人工照护 | 与家庭应用共用当前宠物记录；没有真实 Alexa 接入 |
| 照护工作台 `/#workbench` | 查看受控自动照护演示 | 请求与审批、运行记录、演示设置；虚构 Mochi、硬限制、模拟设备与回执 |
| 原小屋 `/#home` | 保留早期小屋体验 | 兼容入口；新家庭日常使用从家庭应用开始 |

家庭应用支持直达今日 `/#app/home`、照护 `/#app/care`、成长 `/#app/growth`、分身 `/#app/assistant`、家庭 `/#app/family`。登录、刷新和浏览器返回会保留所选入口；官网体验按钮也会进入对应页面。家庭应用和照护工作台采用相同视觉与入口导航，但保留独立登录、数据和操作权限。

## 2026-10-13：工作空间与操作流程

演示口令和家庭演示账号已补齐档案、连续体重、待办/领取/完成照护、系统报告及已确认偏好。用[演示登录](http://127.0.0.1:8834/#workbench)进入后点击顶部“家庭应用”即可体验；样例实际保存、可编辑、刷新后保留，并明确标为虚构。[样例内容、账号与核验](evidence/demo-usage-2026-10-13.md)。

- **今日**：查看当天待办、实际保存的人工完成次数与最近测量；快捷记录体重或观察。小屋保留编辑档案、布置物品和新增宠物，统一使用家庭导航和宠物选择。形象按已保存的猫/狗、毛色、花纹、大小显示。
- **照护**：默认查看待办；今天、逾期、我负责、已完成和全部可切换。“我负责”包含指派给自己或由自己领取的任务；卡片显示负责人、领取人和重复计划下一次时间。
- **成长**：分为概览、实测与饮食、日记与观察、报告。记体重和记观察会直达相应表单；就诊信息卡入口保留在成长页，导出前核对来源和缺项。
- **分身**：提问、人工照护方案和候选记忆分别呈现；候选需主人确认。家庭访客可以查看资料，不显示其权限不允许的提问、记录及确认控件。Alexa 体验由独立网页模拟入口进入。
- **照护工作台**：请求与审批 `/#workbench`、运行记录 `/#workbench/history`、演示设置 `/#workbench/settings`。硬限制始终可见；运行记录可筛选状态和时间排序，证据/调用记录按需展开。演示设置集中修改事实、注入模拟回执、查看原文反馈和创建新会话。
- **响应与草稿**：切宠清空未保存的观察和日记，迟到的档案回执不会关闭另一只宠物的草稿。工作台在已接收请求首次状态返回前临时锁定历史选择，分析/执行期间阻止重复发送；客户端等待到期只停止读取并保留请求编号，可刷新查询后台实际结果。会话失效后迟到响应不能重新打开工作台。

本轮验收、四种屏幕宽度和截图见[工作空间升级记录](evidence/workspace-upgrade-2026-10-13.md)。

## 照护交接与就诊准备

本轮新增功能的完整验证状态见[照护交接与就诊卡验收](evidence/platform-2026-10-12.md)。

- **导出就诊信息卡（诊断资料）**：在成长页选择当前宠物和近 7/30/90 天，生成预览，核对后打印/另存 PDF，或下载可独立打开的 HTML。资料保留年龄依据、最近一次体重的原测量时间、饮食原备注、人工完成照护、历史观察、确认偏好与文字日记。未记录资料不补填，演示测量默认排除。
- **授权照护者访问分身**：家庭管理员在家庭页选择当前宠物和 1/4/24/72 小时期限，创建临时只读链接，自行交给需要了解宠物的人；可随时撤销。护工无须加入家庭，独立入口只展示该宠物的照护资料并支持本地规则问答，不能更改记录、确认照护或操作设备。宠物归档或授权管理员失去权限会永久撤销旧授权，恢复后需要重新创建。
- **访问宠物分身**：分身页和护工独立入口可回顾品种、主人描述的喜好、当前已确认偏好及近期照护事实。问答标注来源与本地规则；提供食物、出粮和实际摄入分别说明。
- **案例与功能演示**：官网 `/#vision` 展示照护交接四步和就诊准备三步，可切换资料卡、来源与缺项。界面为虚构示意，真实导出/授权从登录后的应用进入。

当前链接与账号运行在本地服务，跨设备部署需另行验证。链接持有者在有效期内可读取获授权资料，密钥仅创建时显示；丢失时可撤销旧授权后重新创建。已下载的资料是生成时刻的独立快照，不会随原记录更正自动更新。

外部服务预约、下单、接单、反馈验收、公开市场和支付仍为未来规划，不会因查看官网示例而创建订单。完整构想见[平台与信息卡产品方案](plans/PawTwin_照护平台与就诊信息卡_2026-10-12.md)。

## 家庭应用的功能

| 模块 | 可以完成的事 | 使用时需要知道 |
|---|---|---|
| 宠物小屋与档案 | 添加猫/狗、切换宠物、保存照片、生日与基本信息、确认偏好、摆放物品、归档和恢复 | 房间为俯视图，宠物为正面像素形象；未知资料保持空白 |
| 日常照护 | 安排人工喂食、换水、陪玩、梳毛、洗澡、剪甲、清洁、散步；设置时间、重复周期和负责人 | 人工任务需要人在实际完成后确认；安排任务不会触发设备 |
| 家庭交接 | 领取、转交、编辑、延期、取消、完成任务，查看家庭动态 | 称呼与权限分开；管理员、照护者、访客有不同权限 |
| 成长记录 | 记录实测体重和饮食、保留来源与时间、纠正或删除、查看曲线 | 单次体重不能说明增重或减重；实际摄入与出粮分开记录 |
| 日报与周报 | 回看真实测量跨度、人工照护完成、待办与逾期、饮食记录和统计来源 | 服务运行时自动生成并支持补跑；尚未发送通知 |
| 观察与照片日记 | 记录当天观察、一般观察、已确认偏好与成长照片；保留作者和日期 | 当天观察过期后停止影响建议；修改和删除同步影响后续上下文 |
| 个体分身 | 根据当前宠物档案、成长、记忆、观察与参考回答；检查引用依据；确认人工照护方案 | 默认本地规则；候选记忆需确认；模型文本不授予权限 |
| 家庭管理 | 创建或加入家庭、邀请成员、设置角色和称呼、撤销邀请或访问、设置家庭时区 | 本地身份与数据存储；每个账号有一个当前家庭 |

## 一次完整的日常流程

1. 登录家庭应用，选择当前宠物，在今日概览查看当天计划、逾期事项、下一件照护和最近实测。
2. 记录实际测量、观察或确认偏好，注明来源和发生时间。
3. 在照护页安排任务，或让个体分身提出方案后明确确认。
4. 家人领取或接手，在实际完成后保存完成记录。
5. 回到成长与报告查看变化和来源；需要更正时修改原记录。

App 与 Alexa 网页模拟共享这些家庭记录。页面内的模拟对话会在离开、刷新或切宠后清空；宠物档案、确认记忆和任务保留在本地数据库。

## 实用性与可视化更新

2026 年 10 月 12 日的更新已完成本地验收：

- 今日概览提供照护、体重、观察快捷入口；小屋中的到期待办与全天计划分别标注。
- 照护页先展示队列，支持待办、全部、今天、逾期、我负责、已完成筛选。重复任务显示最近完成与下一次计划，修改标题不会覆盖原时间或周期。
- 从玩具、水碗或窝安排照护会保留对应类型；切换类型不清空已经选择的时间、周期和负责人。
- 成长页提供最近测量摘要、真实时间跨度、全部/30/90 天曲线、纵轴刻度、测量点详情与数据表。相同时刻的不同时间偏移不会形成虚假趋势。
- 日/周报告采用统计卡片，并可展开可读来源和版本。完成次数使用持久化完成事实，旧活动列表截断不再丢失这些次数；当前报告也能计入同一时钟刻度内刚保存的事实。
- 成长、报告与记忆独立读取和重试；晚到的响应不能覆盖其他宠物，访问被撤销后立即清除或遮蔽家庭资料。
- 官网同步实际应用的结构与明确跳转，Alexa 网页模拟入口可发现，原工作台和原小屋继续兼容。

[本轮验收与复现](evidence/usability-2026-10-12.md)包含测试、画面和历史记录兼容限制。

## 能力边界

当前家庭应用使用本地账号与 SQLite，默认分身回答为本地规则。可选 Bedrock 路径有接线与离线测试，真实调用仍需独立验证。Alexa 为网页模拟，PawLink 项圈为概念，设备执行为模拟。

界面只展示有来源的记录，不生成心情、饥饿、健康评分或补填测量。出粮不等于实际摄入，统计趋势不等于诊断。自动照护演示仍必须经过明确审批、硬限制和成功回执。
