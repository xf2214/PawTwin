# PawTwin 展示方案

2026-10-03；基于[本轮功能复验](../evidence/functional-check-2026-10-03.md)。当前可以展示本地原型；视频录制、真实用户试用和正式提交仍待执行。

## 展示主线

**让每位家人接着照顾同一只宠物。**

围绕 Mochi 展示一个连续场景：主人记录成长与偏好，另一位家人读到这些资料，主人确认照护安排，家人领取完成，统计回写。观众应看清“资料如何共享”“谁实际做了什么”“结果有何依据”。

推荐采用 **2 分 55 秒讲解视频 + 5 分钟现场演示 + 1 页检查摘要**。官方视频要求少于三分钟，留出余量。像素小屋负责开场的识别度；中段以可检查的协作结果为主；更完整的功能与模拟设备放在现场延展。录屏应保留“本地”“规则”“Alexa 网页模拟”等界面标签。

## 3 分钟脚本

| 时间 | 画面及实际操作 | 必须让观众看到的证据 | 建议旁白 |
|---|---|---|---|

| 0:15–0:35 | 主人和家人小林两个独立会话快速切换；家庭页显示成员关系 | 两位登录人、同一家庭；小林自选“爸爸”仍为照护成员 | “每位家人使用自己的账号，共享同一份资料，实际记录人可以追溯。” |
| 0:35–1:05 | 成长页展示两条演示称重、曲线与周报；展开“统计依据与版本” | 演示样本标签、1.20→1.35 kg、150 g / 12.5% / 7 天、源记录；摄入未记录 | “这两条是演示样本。变化由程序按实际测量时间计算，未记录的摄入保持缺失；统计依据可以展开检查。” |
| 1:05–1:35 | 主人在助手页确认偏好；切到小林的 Alexa 网页模拟，提问“它喜欢什么” | 待确认→主人已确认；另一账号的新回答引用羽毛棒偏好与上下文版本 | “确认后的公共偏好会被家人使用。App 和网页模拟入口读取同一份宠物上下文。” |
| 1:35–2:10 | 主人选择“陪玩”，填写方案；建立待确认、明确确认；小林同步后领取、完成 | 待确认期间还没有任务；确认后出现任务；家人小林负责，陪玩已完成 | “主人选择照护类型和时间，确认后才安排。另一位家人接手，完成记录归于他的真实账号。” |
| 2:10–2:40 | 主人成长页生成当日日报，显示人工完成 1 次；回到助手删除偏好，小林刷新重新问 | 日报回写；新回答不再引用已删除偏好 | “任务结果进入回顾。偏好也可以纠正或删除，之后的回答会跟着有效资料更新。” |
| 2:40–2:55 | 用结尾卡回顾结果与当前状态 | 使用 STATUS 最新实测数字；本地规则、网页模拟；云接入待完成 | “当前已验证本地家庭协作、准确统计和确认后的照护交接。云身份、真实模型与 Alexa 接入是下一步。” |

3 分钟中不录完整注册表单和邀请码复制过程；预先准备两个演示账号，录制时保留身份切换证据。不要把邀请口令或密码放进画面。

## 排练用数据与操作顺序

用独立预览库和虚构演示家庭准备数据，不动用户原库。启动命令：

```powershell
Set-Location 'C:\Users\11831\Desktop\hks\outputs\pawtwin-app'
./scripts/dev-home.ps1 -Port 8807 -DatabasePath data/extension-preview.db
# http://127.0.0.1:8807/#app
```

1. 两个独立浏览器 profile/session 分别注册“展示主人”“家人小林”；同一 profile 的两个标签页会共享登录，不适合作双账号展示。
2. 主人创建“Mochi 的演示家庭”、默认 Asia/Shanghai；生成邀请，小林加入并设置称呼“爸爸”。不要在新家庭演示自动设备执行权限。
3. 使用默认 Mochi 作为同一宠物：在“成长”录入 2026-09-25 12:00 的 1.20 kg 和 2026-10-02 12:00 的 1.35 kg，两条来源均选“演示样本”。统计日期选 2026-10-02，生成周报。9 月 25 日用于比较基线；周窗口是 9 月 28 日到 10 月 5 日，实际比较跨度是 7 天。
4. 主人“助手”→偏好原文填写“喜欢羽毛棒，饭后先休息”→保存候选→确认记忆。小林“助手”→对话入口选“Alexa 网页模拟”→问“它喜欢什么”。
5. 主人“受控照护方案”必须选择类型 **陪玩**，名称“饭后休息，再陪 Mochi 玩羽毛棒”，计划时间设为家庭当地当前时间或过去一分钟，保证可以完成。先建立待确认，再点“确认安排照护”。这个表单默认类型为人工喂食，录屏前应检查选择正确。
6. 小林“照护”→“同步最新记录”→领取→完成照护；主人“成长”将统计日期选为操作当天，生成日报；只对日报卡核对“人工照护完成 1 次”。
7. 删除公共记忆后，小林刷新并重新提问，展示不再引用旧偏好的新回答。历史回答不会被回写改造，应以新的提问结果为证据。

本轮自动排练已完整执行上述链条。测试采用内存库，因此截图中的账号和资料不会自动保存在 8807 预览库；正式录屏前仍需按此顺序预置。

重拍时为该次演示新建家庭/测试库，或按界面提供的正常操作整理自建演示数据。重复完成不会生成第二次完成记录；同一报告有版本更新。不要为了重拍清空原库或手改数据库计数。

## 5 分钟现场演示

| 时间 | 操作重点 |
|---|---|
| 0:00–0:30 | 小屋、宠物卡和两位成员；先说明当前使用本地原型。 |
| 0:30–1:20 | 成长记录、周报与展开来源；允许现场改变一条演示称重，观察数值和版本更新。 |
| 1:20–2:00 | 确认偏好，切换到另一成员的网页模拟入口重新提问。 |
| 2:00–3:10 | 建立陪玩方案、停在待确认说明此时没有任务；确认后由另一成员领取完成，日报回写。 |
| 3:10–3:45 | 删除记忆后重新提问；根据观众关注补看多宠物隔离或照片日记。 |
| 3:45–4:30 | 可选：在独立第三会话的原 Mochi 演示工作台展示批准、失败或未知回执。提前复位自己的演示状态；清楚标为模拟设备。 |
| 4:30–5:00 | 检查摘要与后续云接入步骤，回答当前已实测范围。 |

可选工作台入口沿用原演示登录，使用 `/#workbench`；新家庭的默认 Mochi 档案不会继承设备执行权。模拟成功出粮、人工照护完成及实际摄入三者分别说明。现场不依赖 AWS 服务、外部模型或真实 Alexa。

## 画面与材料安排

- 主录屏建议 1440×900 或更高的常规桌面视口，字体保持可读；再补 390px 手机宽度约 5–10 秒的导航镜头。完整主流程使用桌面画面，避免长表单挤占手机录屏时间。
- 开场滚动到像素房间；成长段先拍曲线，再滚动到报告；助手和照护段聚焦结果卡片。固定导航位于视口底部，录屏前将目标内容滚到导航上方。全页自动化截图用于验收，不直接代替正式录屏。
- 两个会话用旁白/画面标题清楚标“主人”“家人小林”；切换后保留登录人名称约 1 秒，随后集中显示操作结果。
- 各个“保存”“确认”“完成”动作停留约 1 秒，等成功状态及更新的卡片可见后再切页；必要时点“同步最新记录”。当前是轮询/聚焦同步，不演示成 WebSocket 推送。
- 主视频保持界面标签可见；旁白只说已验证行为。高级说明放进一页摘要：使用的本地技术、统计/来源口径、实测结果、云接入待完成。

## 常见问答与临场恢复

| 情况 | 回应或恢复 |
|---|---|
| 是否已接 AWS / 真实 Alexa？ | 当前展示本地 SQLite、规则回答及 Alexa 网页模拟。新家庭云身份、存储、推理和记忆尚未完成接通验收；真实接入后再补相应调用证据。 |
| 是否能诊断健康或猜测摄入？ | 当前展示可追溯的记录与统计；没有数值品种成长曲线或诊断。摄入缺失保持“未记录”，出粮不等于吃下去。 |
| 是否由 AI 自动安排陪玩？ | 本版由主人选择类型、标题和时间，经确认生成人工任务；规则回答引用有效资料。生成式规划仍待真实模型接入。 |
| 服务重启或登录失效 | 启动同一个独立预览库，重新登录两个演示账号；资料仍保留。先检查 `/healthz`；别把登录失效说成资料丢失。 |
| 另一会话暂未显示新任务 | 确认属于同一家庭/宠物，点“同步最新记录”；稍候正常轮询。 |
| 出现版本冲突 | 同步最新记录后重新建立/确认当前方案；保留冲突提示，说明它在保护并发修改。 |
| 周报不足两次测量或数字不符 | 检查时间、kg/g、有效记录与报告日期。不要用输入框当前默认值代替已保存的事实。 |
| 现场无法继续操作 | 使用本轮截图解释最后已验证状态，明确这是验收留图；视频或截图不能冒充当前在线结果。 |

## 展示准备的执行顺序

1. 按当前脚本在独立预览库预置两位成员与资料，做一次 3 分钟人工计时排练。
2. 录制桌面主流程、手机补镜头与可选模拟回执；核对日期、方案类型、来源标签和身份切换。
3. 将视频剪为 2:45–2:55，配对应英文字幕；保留原始录屏和这份检查报告，数字与画面一致。自动采集见 [录屏指南](capture-guide.md)，本轮实际素材与新会话证据见 [完整度评估](../evidence/hackathon-completeness-2026-10-03.md)。
4. 云演示、家庭试用、公网访问和正式提交作为后续工作；到正式对外材料阶段再核对赛事规则、资格及真实技术要求。

本轮完成的是功能复验和上述展示规划，未录制、发布或提交材料。
