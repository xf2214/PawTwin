# 多 Agent 开发入口

后续先读 [附加计划](../plans/PawTwin_附加开发计划_2026-10-02.md)、[Qoder 接手说明](../QODER_HANDOFF.md) 和当前 TASKBOARD。下方起始任务为历史角色入口，不要求重做已完成功能；新增任务按 EXT ID 认领。
当前未提交代码包含重要 Home/Day-5 内容，不能假设旧 HEAD 工作树包含完整版本。先协调完整基线或串行写路径。

把本项目目录作为每个开发任务的项目，优先通过应用的工作树功能从同一基线提交创建独立分支。一个角色一个工作树。总负责人负责合并；不要让多个独立任务直接写同一个检出目录。

角色入口：

- [后端](backend.md)：先执行 BE-01，完成契约后再派发 BE-02。
- [前端](frontend.md)：FE-01，业务接口冻结前只做界面和组件。
- [AI 与记忆](ai.md)：AI-01，AI-02 依赖反馈和 AWS 条件。
- [云部署](infrastructure.md)：OPS-01，先提供具体方案，不直接收费部署。
- [审查](reviewer.md)：QA-01 或某一任务的独立审查，只读。

给 Agent 的第一条任务应包含：本文件路径、角色文件路径、具体任务 ID、基线提交、允许写的路径、完成标准。角色说明本身不代表全部任务均已授权。

如果工具没有工作树功能，可在项目目录用 Git 为明确的任务创建工作树；操作前检查目录和分支不存在。示例分支命名为 `feat/backend-contract`、`feat/frontend`、`feat/agent`。工作树准备好后先安装锁定依赖并运行基线检查。

阶段完成后采用正常合并或明确的提交拣选，保留提交历史；不得把目录覆盖拷贝当作代码集成。接口变更由总负责人先合入，再让其他分支更新。
